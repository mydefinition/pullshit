# 反馈学习研究笔记

调研日期：2026-10-09。以下是可借鉴的研究，不表示已在 QQ 群中验证有效。

| 工作 | 方法 | 对 pullshit 的启发 | 限制 |
| --- | --- | --- | --- |
| [PAHF (2026)](https://arxiv.org/abs/2602.16173) | 行动前澄清、检索偏好、行动后更新显式记忆 | 学习有条件的群偏好，支持修正旧结论 | 主要在操作和购物任务中使用模拟用户反馈；不能直接代表真实群聊 |
| [Reflexion (2023)](https://arxiv.org/abs/2303.11366) | 将结果反馈转为语言反思，存入经验记忆 | 学习整理上下文和编辑内容的方法，不必微调大模型 | 自我反思可能错误，必须绑定外部证据 |
| [ACE (2025)](https://arxiv.org/abs/2510.04618) | 通过生成、反思、整理增量维护经验手册 | 独立条目更新，避免反复摘要丢失条件和细节 | 经验维护不自动解决反馈歧义和偏好冲突 |
| [Contextual Bandit 新闻推荐 (2010)](https://arxiv.org/abs/1003.0146) | 根据上下文选内容，从反馈更新推荐策略 | 在符合发布约束的候选中平衡利用和探索 | 点击不等于满意；QQ 缺少可靠已读数据 |
| [Implicit Feedback (2008)](https://yifanhu.net/PUB/cf.pdf) | 对隐式行为区分偏好与置信程度 | 表情、回复不能直接等权累计为喜欢分数 | 不建议在首版直接照搬协同过滤算法 |
| [Unbiased Learning-to-Rank (2017)](https://arxiv.org/abs/1608.04468) | 对有偏反馈进行倾向加权学习 | 记录候选池、选择策略与探索概率，关注选择偏差 | 有覆盖和概率估计等前提，日志本身不能消除偏差 |

## 拟采用的闭环

原始反馈 → 归因到具体发布 → 解释对象与含义 → 保存支持/反对证据 → 更新有范围和时效的偏好 → 影响下一次选择。

优先借鉴 PAHF 的闭环与 ACE 的增量记忆。反馈量足够后，再评估 contextual bandit。保持大模型参数不变，也可以通过记忆和轻量排序策略实现持续适应。

个人反馈不能直接升级成全群规则；无反馈视为未知；群规则与软偏好分开。每条偏好保存来源、反例、适用群、时间和版本。

## 首个实验

比较三种方案：无偏好记忆、检索历史反馈、结构化偏好记忆。使用相同候选和相同模型，按时间回放；每一步只能看到当时已有反馈，近重复内容不能泄漏到评估集。

评估后续选材的人工认可率、明确负反馈、上下文完整性和费用；记录成员间分歧。只有已发布内容有线上反馈，未发布内容通过人工抽样标注评估，不假装拥有反事实满意度。
