## 目标与范围

交付一个最小接入验证程序：从少量授权源群接收事件，保存可回放的数据，在一个测试目标群中按人工指令发送测试内容，并记录收发能力及限制。

这一阶段回答三个问题：能收到什么、能可靠发出什么、反馈能归因到什么。结果应能支撑下一阶段开发事件库、内容包和选材流程。

本阶段包含配置、平台适配、最小持久化、受控发送、反馈能力探测及回放验证。选材模型、群口味学习、自动跨群发布、主动搜罗和完整 agent 运行时接入分别按后续路线推进。图片在本阶段验证传输与缓存；内容理解属于 P1。

## 本批开发：P0 上下文还原

状态：实现与自动验证完成；真实文本回取、图片地址刷新和离线缓存复用通过，真实引用/合并转发待样本联调。本批对应下方 04 与 07 的引用、合并转发、媒体与真实回放任务；实现边界见[QQ 接入层设计](qq-adapter.md)，组装原则见[总体设计](design.md#42-组装策略)。

1. **本地上下文查询**：按账号、群及消息 ID 定位原文，保存引用关系；附近消息单独列为上下文线索，保留时间与发送者，引用关系优先。
2. **有界引用回取**：本地缺失时调用只读 `get_msg`，核对返回的账号/群范围与消息身份，缓存成功结果及来源证据。授权变化、撤回、缺失或超时返回明确状态。
3. **合并转发展开**：通过 `get_forward_msg` 展开节点并保持层级、顺序与媒体引用；检测循环与截断，记录来源不能确认的节点。预算已写入默认配置及[字段说明](configuration.md#上下文查询参数)。
4. **接入图片缓存**：上下文中的图片按已有下载边界保存，关联原消息并复用缓存；过期、无法读取和超限各自记录。图片理解按 P1 推进。
5. **只读查询入口与验证**：提供可查本地上下文的 CLI，在线补取显式选择；输出原文、引用链、附近消息、媒体引用及缺失原因。引用/转发模拟测试通过，已收录真实脱敏文本、图片、@ 与表情新增样本；真实回复/转发样本继续采集。

本批验收：查询一条回复消息可返回其原文及引用链；查询合并转发可得到有界节点树和可读取的媒体；内容缺失可辨认；重复查询复用已有证据；只读查询保持发送关闭。

本批之后继续完成真实图片发送、表情取消与查询语义、撤回及断线/重启验证，汇总 P0 能力矩阵，再进入 P1 选材影子运行。

## 执行顺序与阶段验收

顺序：`01 → 02 → 03 → 04 → 05 → 06 → 07 → 08`。开发每项能力时同时补充对应 fixture 与检查，07 集中验证恢复和全链路回放。

第一阶段完成条件：

- 授权消息能持久化，重复事件和账号/群范围正确处理。
- 至少完成文本和图片的真实收发验证；引用与合并转发具有可复现结论及缺失处理方式。
- 人工探测受路由、发送开关和暂停约束；发送不确定状态可保留、核对。
- 反馈能力已实测；支持的信号可正确关联，受限能力具有明确后续方案。
- 断线与重启的恢复行为可复现，离线回放不会触发真实发送。
- 真实执行命令、检查结果、版本与数据保留策略已写入文档。

实际平台缺陷应列出影响和处理决定。基础收发、权限检查、持久化或重复处理未通过时，继续修复 P0；可选反馈能力受限时，以能力矩阵确定后续支持范围。

### P1：影子运行，验证选材

在 P0 事件库基础上搭建内容包、规则初筛、批量模型判别、每日候选清单和成本账本。先准备约 100–300 个覆盖好内容、坏内容、上下文缺失、反讽、图片梗和重复传播的标注样本。按时间拆分并将近重复内容放同一分区，避免评估泄漏。

- [ ] 实现群内人工提名与控制命令入口，校验真实发送者、群范围与角色；引用及转发中的命令保持为普通内容。
- [ ] 在候选流程中按需组装上下文与媒体，接入文本和图片理解，记录结构化判断与模型费用。

### P2：小规模半自动发布

- [ ] 建立业务发布队列与事务 outbox。

批准的候选才发，每群每天最多 3–5 条作为初始试验配置；打通发布账本、回复归因、显式反馈、暂停、发送未知状态。验收：重放不重复发送、暂停阻止待发任务、反馈不串群、不因超时盲重发。

### P3：有限自主和群口味

人工认可率持续可接受、上下文缺失和重复发布可控后，仅对批准类别自动发布。可将近 100 条建议中至少 80% 被认可作为讨论起点，但不能替代风险专项测试。启用群级软偏好、衰减、反例、版本回滚；先与固定策略对照，再考虑小比例探索。

### P4：Agent 适配与主动搜罗

根据搜罗和上下文补全的实际需求选择一种适合 Python 业务程序的 agent 接入方式。领域接口保持不变，只实现一个适配器，验证输出、预算、取消与恢复。在此前即可做不发布的搜罗实验；本阶段将合格来源的搜罗任务接入真实候选和发布流程。
